## Execution order

### 0. Finish current qualification; cleanup decisions agreed

- Preserve the current qualification source/artifacts. The running workflow is
  https://github.com/famulare/ToddlerBox/actions/runs/41169159684 . At audit time,
  unaccelerated fresh installation passed and update-chain qualification was
  starting. Do not call the whole run passed until its final result is checked.
- Download/verify final synthetic evidence and record the exact CI-built artifact
  separately from the host-built local development artifact. Do not silently
  substitute one for the other, even when their source content IDs match.
- The maintainer authorized closing #23 as superseded by #29 and closing #15
  and #19 as completed/satisfactory. Do not require additional parent checks for
  these closures. Retain the historical comments/evidence.
- Keep #29 open until its delivery/qualification gate is satisfied. Record the
  stopped-stroke reproducibility limit explicitly rather than promising a universal
  cure from one successful test. Production 0.5.3 sequence/tag are not allocated.
- Nothing requires reinstalling the existing appliance or changing child work.

### 1. Correct pronunciation (#25)

- Listen to the original word source, its trimmed whole-word replay and the final
  sequence; identify whether the vowel problem is in the source recording,
  edit boundaries, a sound-unit clip or their assembly. Automated speech recognition
  and waveform checks cannot approve pronunciation.
- Correct only the affected content, preferably preserving the voice family.
  Verify provenance/license requirements and retain attribution/source information.
  Regenerate affected cues/frame counts/catalogue/hash records reproducibly.
- Compare genuine baseline/new decoded audio and asset hashes: unrelated words,
  Math numbers, Music and artwork must remain exact. Add focused integrity/cue
  tests, then get human listening approval for /plʌm/ both alone and in the card.
- #19 is closed and needs no additional parent acceptance. Never play a surprise/
  looping tone or raise volume automatically during new audio work.

### 2. Deliberate visible-content speech (#30)

- Keep selecting/first appearance/revelation silent. A visible printed numeral
  speaks only its own value on a deliberate tap. A question-mark tap reveals
  silently; a later tap on the revealed value speaks it. Visible equation operands
  can speak without revealing the hidden result. Keep illustrated objects passive.
- Derive numeral hit rectangles from the actual fitted text layout, with adequate
  non-overlapping touch targets. Preserve the existing full-equation speaker and
  Home layout. Reuse NumberPlayer/SpeechPlayer; no new audio engine or network.
- Verify Reading's already-visible main picture replays the whole word; fix only
  a reproduced missing state. Preserve phoneme/letter controls and rail navigation.
- Test raw finger plus duplicate mouse events, one playback per tap, repeat taps,
  hidden/reveal/visible transitions, cancellation on navigation/Home and missing
  clips. Baseline/new frames should match where no visual change was requested.
- Validate on the standalone session, not only the desktop. Update contract,
  relevant guides and changelog together; do not add assessment or progression.

### 3. Back with chronological history (#24)

- Use a small pure bounded in-memory navigation model shared in behavior across
  the apps. Store example/card identifiers, mode, reveal state and necessary
  illustration identifiers/seed, never decoded surfaces or audio buffers.
- One history per app visit crosses Math modes. Reading's Pictures/abc toggle
  changes presentation only. Sidebar selections count as visits. Back/Next restore
  exact prior state; a new choice after Back truncates only the forward navigation
  branch. This never deletes child documents or saved archive/history files.
- Capture the current revealed state before leaving an entry. Cancel pending
  speech and stale input on navigation; restoring an entry neither speaks nor
  reveals it automatically. At the newest entry, Next retains current random
  generation/no-immediate-repeat behavior.
- Add pure history/branch/capacity tests and app-level cross-mode navigation,
  reveal/audio-cancellation and missing-card tests. Include synthetic UI screenshots
  and genuine old/new frame comparisons outside the intended Back button.

### 4. One diagnostic-image batch (#27)

- Add libinput-tools, evtest, smartmontools and pciutils to the shared image recipe.
  Retain existing ALSA/PulseAudio package entries and the supported pw-play check.
- Inspect package-installed services/presets, especially SMART, and prevent new
  automatic polling/timers/tests. No child UI, scheduled network work or automatic
  package installation on existing appliances.
- Document explicit parent-only, bounded, read-only use and private trace storage.
  No exclusive input grabs. Preserve independent escape and qualified checkpoints.
- In a disposable clean image, check installed versions/command paths and bounded
  basic operations for libinput tools, evtest, smartctl, lspci, speaker-test, aplay,
  alsamixer, pactl, paplay and pw-play. Record which hardware-specific operations
  cannot be established by virtual devices; never claim VM audio is human hearing.
- Record package manifests and confirm no new background unit is enabled. These
  are image-only delivery changes, not part of an app/system bundle's fixed payloads.
  Retain #19's implemented audio tools and documentation without reopening its
  accepted scope. A future ISO is not a prerequisite for updating this HP.

## Integration and closure rules

Use bounded commits per issue on dev/0.5.3-paint (or focused branches based on it),
without modifying any frozen/published artifact. Each source/asset change receives
its own content ID and focused validation; today's VM result cannot qualify future
speech/history changes. Reuse unchanged evidence and perform one final combined
build/VM/physical qualification for the intended 0.5.3 scope. Preserve known-good
rollback, parent-initiated backup/sync and explicit candidate acceptance.

Close issues with a commit/evidence reference and delivery status: distinguish
fixed on dev, locally accepted, merged and released. The maintainer agreed to this execution order and explicitly approved closure
of #23, #15 and #19; the other issues remain open. Keep private device findings outside
public comments, source, screenshots, release assets and diagnostics.
