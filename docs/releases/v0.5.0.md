# ToddlerBox 0.5.0 — existing-install update

This release updates an existing Ubuntu 24.04 x86-64 ToddlerBox appliance;
there is no new OS installer in this release. It includes louder Music,
Reading and Math, natural manual-piano release, and an 80% startup master
volume. Existing settings are preserved until the parent explicitly chooses
the louder defaults. Child work is never replaced.

## Install on the HP

Enter parent mode and save parent desktop work. From the repository checkout,
pull main and install the small USB setup/DNS patch once:

```sh
git pull --ff-only
sudo sh scripts/install-drive-setup-patch.sh
```

This is an explicit trusted-source maintenance patch, not a signed release
migration. It adds USB package discovery and uses the connection's DNS servers
directly. Its backups are private and durable. It neither resets setup nor
removes transfer files. DNS applies at next boot; restarting NetworkManager
applies it immediately but briefly disconnects Wi-Fi.

Then open **ToddlerBox Setup & Maintenance**, choose **Check updates**, and
**Install update**. The signed update installs the application as well as its
audio controls. Merely pulling Git does not update the installed app. Start
the candidate child session, test it, return to parent mode and choose
**Accept tested update**. Rollback preserves child work and previous software.

To opt into the louder levels on the existing HP, run in parent mode after
installing the update:

```sh
sudo toddlerbox-maintenance --action audio-defaults
```

Start a new child session. This sets Music to 100%, Reading/Math to 70%, and
startup master to 80%, with a first-configuration backup. Normal updates do
not reset custom gains. Hardware listening and preferred volume remain a
parent check; the VM's virtual speakers cannot calibrate the HP speakers.

Reopen **Set Up ToddlerBox Drive** to rerun USB discovery. A package and its
adjacent `.sha256` file belong at the USB volume root. Public GitHub releases
contain no family package, photos or Google authorization.

## Distribution boundary

The signed update uses the existing updater's fixed destinations and resident
recovery protocol. USB setup and NetworkManager's new policy use the separate
source patch above because those destinations are outside the resident signed
update allowlist. The release does not quietly enlarge that trust boundary.
Fresh OS installation continues to use the separately qualified 0.4.0 ISO;
apply this update afterward. See [updates](../updates.md) and
[validation](../../VALIDATION.md) for evidence and remaining limits.
