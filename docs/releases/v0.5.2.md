# ToddlerBox 0.5.2 — signed update

**Published; exact build VM-qualified and production-signed.** Target: Ubuntu 24.04
x86-64, v1 child-data schema, signed sequence 5. See the
[0.5.2 release](https://github.com/famulare/ToddlerBox/releases/tag/v0.5.2).
Publication does not itself advance the public main stable catalogue from 0.5.1.

## Included in the in-place update

- Durable Paint saves and interrupted-save preservation; blank/unchanged archive
  deduplication in Paint and Typing without deleting existing work.
- Home can leave with pending saves; parked work remains available and retries
  saving. Retention in memory is never reported as a durable save.
- Typing input bounds and resilient document loading; safe config/icon fallbacks;
  consistent Reading/Paint decode-error handling.
- Photos thumbnail invalidation based on source contents and requested size,
  including replacements that preserve timestamps. Legacy derivatives regenerate
  in the background; originals are untouched.
- The existing allowlisted session, maintenance and update/install tools, including
  authenticated compatibility with the published updater and durable publication.

## Preserved boundary

The fixed eleven-file update and resident restore tables stay unchanged. Existing
child work, parent configuration, credentials, device identity, setup state and
resident recovery remain outside the versioned app release.

This update does **not** replace the resident sync worker or its image-safety copy,
boot recovery gate, firstboot, sysctl or GRUB. Their dev-branch changes require a
separately designed and qualified migration or future image. Installer diagnostic
tools are also a future-image task. No reinstall is part of this release.

## Gates before use

1. Resolve synthetic regression tests and pass Linux CI, including root-worker
   tests against Ubuntu Pillow, without weakening production safety guards.
2. Build from one committed source identity; retain the package manifest, bundle
   checksum, embedded app checksum and exact source/content IDs.
3. Qualify that exact bundle against the published signed 0.5.1 baseline on a
   disposable VM: install, supervised candidate frames, acceptance, rollback and
   interrupted-update/restore recovery. Preserve synthetic work, config and
   resident image-only bytes. Record actual results in VALIDATION.md.
4. Following explicit parent-authorized recovery of a lost signing identity, the
   candidate carries the old and replacement public keys. The parent installs the
   replacement trust anchor locally; the maintainer signs with its root-only private
   key. Other existing appliances require the same explicit trust recovery before
   they can verify releases signed only by the replacement key. Normal signed
   updates do not ask parents to authenticate hashes.
5. Before the live update, privately verify a child-data backup. Parent-initiate
   the signed update and test the real candidate's touch, Paint/Typing saves,
   New/Recall/Home, audio and independent parent escape. Accept only after real
   supervised testing and explicit parent confirmation; retain known-good rollback.
